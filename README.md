# Лабораторная работа 3: редакция новостного издания

Spring Boot REST API для предметной области «редакция новостного издания». Это развитие второй лабораторной: данные больше не хранятся в оперативной памяти, а сохраняются в PostgreSQL.

## Что реализовано

- PostgreSQL 16 в Docker Compose и отдельный пользователь `editorial_app` для приложения;
- доступ к БД только из переменных окружения, файл `.env` игнорируется Git;
- пять сущностей с внешними ключами, уникальными ограничениями и `CHECK`-ограничениями;
- полный CRUD для пользователей, рубрик, статей, рецензий и выпусков;
- пять транзакционных бизнес-операций;
- демонстрационные данные в каждой таблице;
- IntelliJ HTTP Client-коллекция `requests/editorial-lab3.http`;
- тесты бизнес-сценариев на H2 и отдельный интеграционный тест с настоящим временным PostgreSQL. H2 используется только для быстрых unit/integration-проверок, рабочая БД — PostgreSQL.

## Предварительные требования

- JDK 17 или новее;
- Docker Desktop с Docker Compose;
- IntelliJ IDEA с поддержкой Maven.

## Быстрый запуск в IntelliJ IDEA

1. Откройте корневую папку как Maven-проект (`pom.xml`) и дождитесь загрузки зависимостей.
2. Скопируйте `.env.example` в `.env` и замените оба пароля на собственные. Файл `.env` не добавляется в Git.
3. В терминале из корня проекта выполните `docker compose up -d`. Контейнер создаст БД, таблицы, ограниченного пользователя приложения и тестовые записи.
4. В **Run | Edit Configurations** создайте конфигурацию `Application` с main class `org.example.lab3.Main` и добавьте в Environment variables:

   ```text
   SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/editorial_lab
   SPRING_DATASOURCE_USERNAME=editorial_app
   SPRING_DATASOURCE_PASSWORD=<APP_DB_PASSWORD из .env>
   ```

5. Запустите `Main`. API будет доступен по адресу `http://localhost:8080/api`.
6. Откройте `requests/editorial-lab3.http` в IntelliJ и выполняйте запросы сверху вниз. Коллекция создаёт собственные данные, проводит статью через редакционный цикл и показывает CRUD-запросы.

Для запуска тестов используйте Maven goal `test` в окне Maven. Docker для тестов не нужен: быстрые сценарии используют H2, а `PostgreSqlStartupIntegrationTest` временно запускает настоящий PostgreSQL, подключает приложение ограниченным пользователем, выполняет REST-запрос и проверяет запрет DDL для пользователя приложения.

> Скрипты из `db/init` выполняются PostgreSQL только при первом создании тома `postgres_data`. Если его удалить, данные БД будут потеряны и скрипты выполнятся заново.

## Модель данных

```text
editorial_users 1 ---- * articles * ---- 1 editorial_sections
                             |
                             + ---- * editorial_reviews

articles * ---- * edition_issues  (через issue_articles)
```

| Таблица | Важные правила целостности |
| --- | --- |
| `editorial_users` | Уникальное имя, роль только `AUTHOR`, `EDITOR`, `CHIEF_EDITOR`. |
| `editorial_sections` | Уникальное название и флаг возможности публикации. |
| `articles` | Автор и рубрика обязательны; заголовок и текст не могут быть пустыми; статус ограничен перечислением. |
| `editorial_reviews` | Рецензия всегда привязана к статье, решение — `APPROVED` или `REJECTED`. |
| `edition_issues` | Уникальная дата выпуска, фиксированный набор статусов. |
| `issue_articles` | Связь «многие-ко-многим» без дубликатов пар статья-выпуск. |

Внешние ключи используют `RESTRICT`: нельзя удалить пользователя, рубрику или статью, на которые ссылаются рабочие данные. Такие же проверки выполняет сервис до операции удаления, поэтому клиент получает понятный HTTP 400/409 вместо повреждения данных.

## Права доступа к БД

`editorial_admin` создаёт структуру при инициализации контейнера. Само приложение подключается как `editorial_app`. Для него выданы только `CONNECT`, `USAGE` схемы, `SELECT`, `INSERT`, `UPDATE`, `DELETE` для таблиц и доступ к последовательностям. Прав на `CREATE`, `ALTER`, `DROP`, создание ролей и баз данных у пользователя приложения нет.

## REST API

Для всех пяти ресурсов реализован единый CRUD-шаблон:

| Ресурс | Базовый путь |
| --- | --- |
| Пользователи | `/api/users` |
| Рубрики | `/api/sections` |
| Статьи | `/api/articles` |
| Рецензии | `/api/reviews` |
| Выпуски | `/api/issues` |

Поддерживаются `GET /`, `GET /{id}`, `POST /`, `PUT /{id}`, `PATCH /{id}` и `DELETE /{id}`. Ответы содержат только DTO, а не JPA-сущности, поэтому API не раскрывает внутренние графы объектов и не зацикливает JSON.

## Бизнес-операции

| Операция | HTTP | Правило |
| --- | --- | --- |
| Отправить статью на проверку | `POST /api/business/articles/{articleId}/submit` | Только `DRAFT` -> `SUBMITTED`. |
| Провести редакторскую проверку | `POST /api/business/articles/{articleId}/review` | Создаёт рецензию и меняет статус статьи на `APPROVED` или `REJECTED` в одной транзакции. |
| Включить статью в выпуск | `POST /api/business/issues/{issueId}/articles/{articleId}` | Выпуск должен быть `PLANNED`, статья — одобренной, её рубрика — доступной для публикации. |
| Опубликовать выпуск | `POST /api/business/issues/{issueId}/publish` | Публикует непустой выпуск и все его одобренные статьи одной транзакцией. |
| Отменить выпуск | `POST /api/business/issues/{issueId}/cancel` | Только для `PLANNED`; освобождает связь со статьями и переводит выпуск в `CANCELLED`. |

Операции с выпуском или рецензией затрагивают как минимум две сущности. Все пять операций зависят от текущего состояния данных и отклоняют недопустимые переходы.

## Структура проекта

```text
src/main/java/.../models       JPA-сущности и статусы
src/main/java/.../repositories Spring Data JPA-репозитории
src/main/java/.../services     CRUD и транзакционные бизнес-правила
src/main/java/.../controllers  REST API и обработка ошибок
src/main/java/.../dto          входные и выходные DTO
db/init                        создание пользователя, схема и демо-данные PostgreSQL
requests                       коллекция запросов IntelliJ HTTP Client
```

## Безопасность конфигурации

Не добавляйте `.env`, реальные пароли или строку подключения с паролем в Git. В репозитории находится только `.env.example` с демонстрационными значениями. Перед сдачей достаточно показать преподавателю свой локальный `.env`, не публикуя его содержимое.
